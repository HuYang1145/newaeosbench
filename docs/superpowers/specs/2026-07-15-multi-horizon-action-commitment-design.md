# 多时间尺度动作持续预测设计

## 1. 背景与目标

当前 Stage3-200k Actor 在每个仿真秒根据当前状态独立输出任务 logits，并通过
`argmax` 为每颗卫星选择空动作或一个进行中任务。动作分支使用单时刻
CrossEntropy 监督，输入中没有显式上一任务 id、已持续时间或最小持续承诺。

现有轨迹诊断表明：模型同时存在大量几乎无贡献的一秒短脉冲和少量占主要工作时间的
长稳定观测段。任务本身要求连续观测 15--60 秒，但有效长片段从开始选择到首次可见
往往需要更长的姿态机动时间。因此，本设计的目标不是把 Basilisk 仿真步长从 1 秒
改为 5 秒或 30 秒，而是让策略显式建模“当前任务还值得持续多久”。

成功标准以正式调度质量为主：降低 `CS_paper`，同时完整报告
`CR/PCR/WCR/TAT_s/PC_Wh`。逐秒动作 top-1 accuracy 只作为训练诊断，不能替代
Basilisk 闭环评估。

## 2. 方案比较与结论

### 2.1 固定最小保持时间

模型仍可每秒推理，但非空动作一旦被选中，固定保持 5 秒或 30 秒。该方案改动小，
适合验证“短脉冲是否是当前完成率低的主要原因”，但会强制延续错误动作，因此只作为
阶段一因果消融，不作为最终策略。

### 2.2 自适应持续预测

在现有任务 logits 之外增加多时间尺度持续预测：

```text
p_continue_5
p_continue_15
p_continue_30
```

模型以 5 秒为基本承诺单位，每 5 秒决定是否继续；任务完成、截止或退出进行中集合时
允许立即终止。15 秒和 30 秒主要作为长期辅助监督，不直接形成不可中断的 15/30 秒
锁定。这是推荐的正式方案。

### 2.3 直接预测未来动作序列

一次输出未来 5--30 个动作会受到未来任务释放、任务完成、姿态和电量状态变化影响，
训练和解码误差容易累积。第一轮不采用该方案。

## 3. 总体数据流

```text
当前仿真状态
  -> 原 Stage3 Transformer 任务 logits
  -> 当前任务和历史任务状态
  -> 5/15/30 秒持续预测
  -> 5 秒基本承诺状态机
  -> Controller + Basilisk 每秒推进
  -> 新状态重新观测
```

Basilisk 只用于离线标签和正式评估，不进入 Transformer forward 或在线候选打分热
路径。

## 4. 阶段一：固定保持时间因果消融

### 4.1 实验问题

阶段一只回答一个问题：

> 在不改变 Stage3 参数和任务排序的前提下，抑制非空任务的一秒短脉冲能否提高正式
> 调度质量？

### 4.2 策略定义

增加可配置的 `min_action_hold_seconds`，比较三个设置：

```text
1 秒：精确复现当前 baseline
5 秒：主实验
30 秒：过长保持的风险对照
```

固定保持策略按卫星独立维护全局 task id 和剩余保持秒数：

1. 空动作不锁定，每秒都允许重新选择，避免错过新释放任务。
2. 新选择的非空任务锁定 `H` 秒；锁定期间仍运行模型和 Basilisk，但执行动作保持为
   同一个全局 task id。
3. 使用全局 task id，不保存进行中任务列表的相对索引，避免列表变化后指向错误任务。
4. 如果任务完成、截止或不再属于进行中任务集合，立即解除锁定并执行当前模型选择。
5. 阶段一不根据可见性、logit margin 或 TimeModel 分数提前退出，否则会同时引入多项
   变量，无法判断固定持续时间本身的作用。
6. `H=1` 必须逐动作精确复现原始 greedy rollout。

### 4.3 实现边界

阶段一预计只涉及：

- `tools/rollout_model_trajectories.py`：增加保持状态与命令行参数；
- `tests/test_rollout_model_candidates.py`：增加 baseline 等价、全局 id 映射、空动作不
  锁定、任务退出后解锁以及 5/30 秒边界测试；
- 独立结果目录和运行脚本；
- 实验完成后在 `改进日志.md` 追加讨论、协议、结果和结论。

不修改 `JointModel`、训练数据、checkpoint、Basilisk 物理逻辑或正式指标公式。

### 4.4 评估协议

使用同一个 Stage3-200k checkpoint、相同 seed 和相同场景，对
Val Seen/Val Unseen 进行同场景比较：

```text
单场 smoke
-> 2+2 场：H=1/5/30
-> 只有 H=5 出现可信改善时，扩大到 8+8
-> 8+8 通过后才考虑完整 Val 64+64
-> 完整 Val 通过前不运行 Test
```

每个设置报告：

- `CR/PCR/WCR/TAT_s/PC_Wh/CS_paper`；
- 一秒非空片段占片段数和工作秒数；
- `任务 -> 空闲 -> 任务` 短脉冲比例；
- 非空动作下一步直接可见率；
- 获得正进度的任务覆盖率；
- 重复冗余率；
- 推理耗时。

### 4.5 阶段一停止门槛

阶段一不是通过减少切换数量自动判定成功。进入 8+8 的最低条件为：

1. `H=5` 的 `CS_paper` 优于同场景 `H=1`；
2. `CR/PCR/WCR` 任一项下降不超过 0.5 个百分点；
3. 一秒短脉冲工作量明显下降；
4. 直接可见率和获得正进度的任务覆盖率不能同步下降；
5. `H=30` 只作为风险对照，不因切换更少而优先选择。

若 `H=5` 和 `H=30` 均退化，则停止固定保持路线，结论记为“任务选择错误比动作切换
更关键”；不得通过继续增大保持时间掩盖问题。

## 5. 后续阶段：自适应持续预测

阶段一支持持续性假设后，再从现有离线轨迹构造未来 5/15/30 秒的多尺度标签。标签
需要包含上一任务、已持续时间、未来动作连续性、可见性、进度、完成和截止状态，并按
`t` 动作最早影响 `t+1` 状态的因果关系对齐。

第一轮冻结 Stage3 主体，仅训练轻量持续头。持续头使用当前卫星特征、当前所选任务
特征、任务与空动作 logits、top-1/top-2 margin、上一任务、已持续时间、任务剩余
时间、进度和 TimeModel feasibility。输出满足
`p_continue_30 <= p_continue_15 <= p_continue_5` 的持续概率。

正式推理以 5 秒为基本承诺单位。每个承诺边界由持续头决定继续、切换或空闲；任务
完成、截止或退出进行中集合时立即解除承诺。只有冻结主体的小头在完整 Val 上获得
稳定收益后，才考虑联合微调 Transformer。
