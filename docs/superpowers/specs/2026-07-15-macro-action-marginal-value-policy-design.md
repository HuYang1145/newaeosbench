# 多时间尺度宏动作边际价值策略设计

## 目标

把当前“每秒重新选择 `task_id`”的策略改造成联合输出
`(task_id, commitment)` 的半马尔可夫决策策略，其中
`commitment ∈ {1, 5, 15, 30}` 秒。模型不仅学习下一秒模仿标签，还要学习一个
卫星—任务边在不同持续时间内带来的可见性、任务进度、完成和重复浪费结果。

成功标准不是单独降低切换率，而是在正式 Basilisk 评估中降低 `CS_paper`，并完整
报告 `CR/PCR/WCR/TAT_s/PC_Wh`。同时必须报告一秒动作率、动作平均持续时间、重复
冗余率、合理接力率、top-k 覆盖率和推理耗时。

## 现状与问题

当前 Actor 输出每颗卫星的任务 logits，在线 greedy 策略每秒重新选择一次任务。
已有轨迹只能观测策略实际保持期间的结果；一秒动作在 5/15/30 秒窗口内几乎全部
被截尾，不能回答“如果继续保持会怎样”。

现有 `local_action_branch.py` 能在一个决策时刻覆盖一颗卫星的一步动作，但后续立即
交回冻结 Actor；它适合比较单步扰动，不等价于真正的 5/15/30 秒强制持续分支。
因此本改造需要同时改变离线分支生成、训练目标和在线执行语义。

## 方案比较

### 方案 A：联合任务与持续时间宏动作策略（采用）

Transformer 保留现有任务表示，在每条卫星—任务边上增加多时间尺度结果头；联合
分配器先选择任务，再由持续时间头选择 1/5/15/30 秒。在线控制器维护承诺状态，
只有在承诺到期或安全中断条件满足时重新规划。

优点是训练目标、模型输出和在线行为一致，能够直接减少一秒抖动与无进度重复。
缺点是改动跨越数据、模型、损失和推理控制器，必须分阶段验收。

### 方案 B：Actor 后置 Graph-Q 重排器

保留 Actor，每秒生成 top-k 联合动作，再由 Graph-Q 选择。改动较小，但 Actor 本身
仍不会表达持续时间，且候选池没有好宏动作时重排器无法补救。

### 方案 C：固定最短保持规则

greedy 选中任务后固定保持 5 或 30 秒。实现简单，但会把不可见、已完成或过期任务
也机械保持，已有 P3.2 结果已经说明固定保持不能作为最终方案。

## 总体架构

### 1. 宏动作表示

每颗卫星的在线动作状态包含：

- `task_id`：当前承诺任务，`-1` 表示空动作；
- `commitment_seconds`：模型选择的 1/5/15/30 秒；
- `remaining_seconds`：当前承诺剩余时间；
- `start_time`：本次宏动作开始时刻；
- `interruption_reason`：到期、完成、任务关闭、候选消失或安全失效。

模型每次重新规划时输出任务 logits 和所选边的持续时间 logits。空动作也允许选择
持续时间，但默认只承诺 1 秒，避免长时间空闲。

### 2. 多时间尺度边际价值头

对每条卫星—任务边复用现有任务 Encoder 和卫星 Decoder 表示，构造边表示后输出：

- `visible_probability[4]`；
- `progress_gain[4]`；
- `completion_probability[4]`；
- `redundancy_probability[4]`；
- `duration_value[4]`。

`duration_value` 不是不可解释的 3600 秒最终奖励，而是由上述短期物理结果和局部
偏好标签共同训练的排序分数。持续时间头从所选边的四个 `duration_value` 中选择。

### 3. 联合分配与重复抑制

现有 task logits 仍负责候选覆盖。联合分配阶段同时消费：

- Actor task logits；
- 多时间尺度边际价值；
- 当前承诺任务与剩余时间；
- 多卫星对同一任务的选择计数；
- 传感器类型兼容性和任务状态。

未到期承诺默认形成硬约束，其他卫星对同任务的边根据冗余概率降权。任务需要接力
或并行贡献时不做绝对互斥，避免把合理协作误判为重复。

### 4. 承诺执行控制器

控制器不调用在线 Basilisk 预测，只维护轻量状态。承诺只在下列条件中断：

- 任务已完成、失败、关闭或不再 ongoing；
- 当前任务从候选任务集合消失；
- 任务与卫星传感器类型不兼容；
- 模型预测的继续价值低于安全阈值，且存在超过切换 margin 的替代边；
- 承诺时间耗尽。

默认不因一秒 logits 波动中断，从而让持续时间选择真正影响执行路径。

## 反事实数据生成

### 决策点

优先采样：

- `idle → task → idle`、`task → idle → task` 和 `task A → task B → task A`
  一秒脉冲；
- 多颗卫星同时选择同一任务但没有直接可见结果的重复边；
- Actor top-k 分数接近、持续时间不确定的边。

### 分支协议

每个决策状态只重放一次前缀，并从同一状态生成宏动作分支：

- 当前 Actor 动作，持续 1/5/15/30 秒；
- 保持上一任务，持续 1/5/15/30 秒；
- Actor top-k 替代任务，优先生成 5/15 秒，必要时生成 30 秒。

强制持续期间只固定目标卫星的任务，其他卫星继续使用同一个冻结 Actor。窗口结束后
停止分支，不扩展到完整 3600 秒。Basilisk 只在该离线生成过程和正式评估中运行。

### 标签

每个分支保存原始、可解释结果：直接可见秒数、进度增量、任务完成、功耗、切换数、
一秒动作数、重复卫星秒数和提前失效原因。相同决策状态的分支构成 pairwise 排序
标签；不把不同状态或不同场景的最终 `CS_paper` 强行归因给单条边。

## 训练流程

### 阶段 B1：冻结 Actor 表示，训练结果头

从当前 Stage3 checkpoint 加载 Encoder/Decoder，冻结主干，仅训练边际价值头和持续
时间头。损失包括带 mask 的 BCE/MSE、多分支 pairwise ranking loss。只有真实完成
窗口或出现事件的标签参与对应 horizon 监督，截尾标签不作为负样本。

### 阶段 B2：联合微调

解冻 Decoder 最后一个 block 和联合分配头，保留原 CE imitation loss，加入小权重
结果预测和排序损失。Encoder 继续冻结，避免小规模反事实数据破坏基础任务表示。

### 阶段 B3：端到端可选微调

只有 B2 在完整 Val 上优于 Stage3 基线，才允许低学习率解冻全部模型。PPO 不属于
本阶段，除非监督式宏动作策略已经证明有效。

## 数据与代码边界

新增实现使用独立模块，不覆盖现有 P3.1/Graph-Q 文件：

- `macro_action.py`：宏动作状态和在线承诺控制；
- `macro_action_branch.py`：真正强制保持 1/5/15/30 秒的离线分支；
- `marginal_value_head.py`：边结果头、持续时间头和损失；
- `macro_action_dataset.py`：分支样本、mask 和 batch；
- 独立的生成、训练和评估工具与配置。

正式接入 `Model/JointModel` 时通过显式配置开关启用。旧 checkpoint 在开关关闭时行为
必须保持不变；新头缺失时不得静默启用随机初始化策略。

## 错误处理与恢复

- 同一分支对的决策状态签名必须完全一致，否则拒绝生成训练样本；
- 强制任务失效时记录 `invalidated`，剩余窗口作为截尾，不伪造负标签；
- 不允许任务 ID、ongoing task 索引和模型 logits 静默错位；
- 每个长任务使用独立输出目录、日志和 checkpoint，不覆盖现有轨迹；
- 所有改动按小提交保存，可通过 `git revert` 单独撤销。

## 测试与验收

### 单元与集成测试

- 强制宏动作确实连续执行指定的 1/5/15/30 秒；
- 完成、关闭或候选消失能安全提前中断；
- `action[t] -> outcome[t+1]` 对齐正确；
- 截尾标签不进入负样本损失；
- 旧 checkpoint 在功能关闭时 logits 与原实现一致；
- 新模型完成一次真实 forward/backward/optimizer step；
- 在线推理路径不调用 Basilisk 或完整轨道传播。

### 阶段门槛

1. 先在 2 个场景生成小样本，证明四种持续时间产生可区分结果；
2. 扩展到 16 个训练场景，结果头在场景隔离验证集上优于常数与 Actor-logit baseline；
3. 运行完整 64 seen + 64 unseen Val，与 Stage3 checkpoint 同协议比较；
4. 只有 `CS_paper` 改善且主要指标没有不可接受退化，才进入正式模型主线。

不预先承诺准确率一定提升；如果局部标签预测提升但正式指标不升，必须分别检查候选
覆盖、持续时间校准、联合分配和控制器中断逻辑，而不是继续盲目扩大模型。
